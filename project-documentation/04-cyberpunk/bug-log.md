# Cyberpunk 2077 bug log

Master table of every Cyberpunk-specific bug recorded in the repository and its
history. Columns: symptom, how it was found (log, crash report, trace, tool),
root cause, fix, files, and the commit that carries the fix (short hash, branch
`phase6-supertuxkart`).

Paths are repository-relative. Diagnostic tags (`[crash]`, `[fs]`, `[gpu]`,
`[mem]`, `[focus]`, `[cursor]`, `[perf]`, `[budget]`, `[vmtags]`) are the
lines the host writes to `Documents/runtime-stderr.log` (or the live console).

## Notes on the table

- Bug 1: the initializer index `#6191` was printed by the crash reporter
  (`initializer ... #%u`) on the phone during bring-up; device logs aren't committed.
- Bug 2: "Failed to find any archives" is the game's own log message, seen in device logs
  during bring-up. The fix is the case-insensitive `ci()` path resolver.
- Bug 4: `signal 11` (SIGSEGV) was reported by the crash handler on the phone. The fix and
  root cause are from `b5dd60b` and the stub comments in `phase8/runtime/CPDesktop.m`.
- Bug 13 is the open leak hunt. The fix commit is partial telemetry; see `memory.md`.
- Bug 29 has no recorded resolution.
- Bugs 20 and 21 are tuning decisions as much as bugs; they are kept because they
  changed the shipped behaviour.
- Rows 9, 14, 17, 18, 23 to 26 and 28 name the symptom as the commit message
  describes it; where the commit gives no symptom, the cell says so.
